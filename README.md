# 飲控 App

以 Google 試算表為資料庫、照片存在自己的 Google Drive、部署在 GitHub Pages 的個人飲食紀錄工具。

---

## 一、第一次架設

### 步驟 1：建後端（Google 試算表 + Apps Script）

1. 建立一個新的 Google 試算表，隨便命名（例如「飲控資料」）。
2. 工具列選「擴充功能 → Apps Script」。
3. 把 `apps-script/Code.gs` 的內容整份貼進去，蓋掉原本的 `myFunction`。
4. **修改第一段的 `API_TOKEN`**，改成你自己的隨機字串（建議 32 字元以上，可用密碼產生器）。
5. 在編輯器裡手動執行一次 `setupSheets`，會建好 Foods / Logs / Body / Meta 四張工作表。第一次執行會跳授權，按同意。
6. 「部署 → 新增部署作業 → 類型選『網頁應用程式』」：
   - 執行身分：**我**
   - 有權存取的人：**所有人**
7. 複製部署後的網址（結尾是 `/exec`）。

驗證：在瀏覽器打開 `<你的網址>?action=ping`，應該看到 `{"success":true,"version":"diet-1.0.0","authed":false}`。

### 步驟 2：前端放上 GitHub Pages

1. 在 GitHub 建一個 repo（例如 `diet-tracker`），把這個資料夾的內容推上去。
2. repo 的 Settings → Pages → Source 選 `Deploy from a branch`，branch 選 `main`、資料夾 `/ (root)`。
3. 約一分鐘後開 `https://<你的帳號>.github.io/diet-tracker/`。

### 步驟 3：在 App 裡設定

第一次開啟會出現「設定連線」：

- 貼上 Apps Script 網址與 API token，按「測試連線」確認（第一次喚醒約 5–10 秒）。
- Gemini API key 可留空，之後在「我的」頁補。
- 選要不要上鎖：**不上鎖**（開啟直接進入）、**連連看圖形鎖**（3×3 一筆畫）、**手把符號密碼**。選了鎖要做兩次確認。之後隨時可以到「我的 → 登入鎖」改。

### 步驟 4：加到手機主畫面

用手機瀏覽器開啟後，Safari 選「加入主畫面」、Chrome 選「安裝應用程式」。之後會像一般 App 一樣全螢幕開啟、有獨立圖示。

## 二、日後改版

前端與後端是兩套版本，要分開處理。

**前端**：改完程式碼後更新 `js/config.js` 的 `APP_VERSION`，`git push` 即可。GitHub Pages 約一分鐘後自動更新，畫面最下方會顯示版本號可以核對。

**後端**：貼上新的 `Code.gs` 之後，**必須「部署 → 管理部署作業 → 編輯（鉛筆圖示）→ 版本選『新版本』→ 部署」**。只按儲存不會生效，這是最常見的踩雷點。改完把 `SCRIPT_VERSION` 一起改掉，用 `?action=ping` 確認線上跑的是哪一版。

## 三、資料放在哪

| 位置 | 內容 |
|---|---|
| 試算表 `Foods` | 食物庫。每一列是一項食物的每單位營養成分、單價、使用次數 |
| 試算表 `Logs` | 攝入紀錄。營養素是記錄當下的**快照**，之後修正食物庫不會回頭改到歷史 |
| 試算表 `Body` | 體重、體脂率 |
| 試算表 `Meta` | 個人資料與每日目標（key-value，值是 JSON） |
| Google Drive `飲控App照片` | 上傳的食物照片，表格裡只存連結 |
| 瀏覽器 localStorage | 上述資料的快取，加上**加密後的**連線設定 |

試算表本身有「檔案 → 版本記錄」，任何改壞刪錯都能還原到任意時間點，這是最實用的一道保險。

## 四、同步怎麼運作

這是一個會刪東西的 CRUD App，所以用的是「雲端為唯一真相」的模型：

- **讀**：每次開啟拉一次雲端，整包取代本機快取。不做聯集合併 —— 聯集無法表達「這筆被刪了」，會讓 A 裝置刪掉的東西被 B 裝置的舊快取救回來。拉取之前會先把本機還沒上傳的送出去，否則整包取代會讓那幾筆從畫面上消失。
- **寫**：更新本機後立刻回到畫面，寫入排進佇列，由背景合併成**一次** `batch` 請求送出。送出的內容仍然是逐列的 `upsertFood` / `deleteLogs`，從不整包覆蓋，所以就算某台裝置的快取是舊的，也只會動到它指定的那一列。
- **逐筆回報**：後端會回每一筆的成敗，用戶端只把失敗的留在佇列裡，成功的不會重送造成重複。

### 兩種上傳方式（我的 → 上傳方式）

**背景自動上傳（預設）**：操作完不用等，上傳在背景進行。連續幾個動作會合併成同一批，所以記一筆照片判讀只會產生一次請求，不是以前的兩趟。

**手動上傳**：全部先存手機，按按鈕才上傳。適合想完全掌控時機的情況，但要知道代價 —— 未上傳的資料只存在這支手機的瀏覽器裡，清除瀏覽資料、換手機、或系統回收儲存空間都會一併消失，而 Google 試算表是唯一的備份。

### 同步出問題時的排查順序

1. 開 `<網址>?action=ping`，確認 `version` 是不是你最新改的那版。不是 → 沒有建立新版本，回去看第二節。
2. 「我的 → 連線設定 → 測試連線」，看 token 對不對。紅字會寫出最後一筆失敗的原因。
3. 開發者工具 Network，確認請求真的打到 `script.google.com`。若打到奇怪的網址，通常是瀏覽器自動填入汙染了網址欄。
4. Apps Script 編輯器 → 執行項目，看該時間點有沒有 `doPost` 的紀錄。

## 五、安全性的實話

**真正保護資料的是 token，不是登入鎖。** 網址與 token 都不寫在原始碼裡，是你自己輸入後才存進這台裝置。所以看到 GitHub 上這個公開專案的陌生人，打開網址只會看到一個空殼，沒有任何資料，也改不了任何東西。這一層不管有沒有上鎖都永遠有效。

**登入鎖只多防一種情況：別人拿到你已設定好的手機。** 三種模式的取捨：

| 模式 | 強度 | 適用 |
|---|---|---|
| 不上鎖 | 無。token 明文存在該瀏覽器 | 只在自己手機上用，不介意手機被別人拿去操作 |
| 連連看圖形鎖 | 3×3 一筆畫，一個手勢完成 | 想要一點保護又不想按很多下 |
| 手把符號密碼 | 8 種符號 × 最多 16 位 | 要最高強度 |

上鎖模式下，設定會用該組代碼經 PBKDF2 + AES-GCM 加密後才存，代碼錯就解不出 token，App 連不上資料。連錯 10 次會清掉本機密文，所以線上暴力破解無效；但擋不住把 localStorage 整個拷走離線破解。

**API key 不會進試算表。** Gemini key 和 token 一樣只存在本機。

換手機或清了瀏覽器資料，要重新輸入網址與 token。建議把它們另外記在密碼管理員裡。

## 六、AI 判讀的界線

拍照辨識與名稱查詢交給 Gemini，但有三道限制：

1. 有營養標示照時以標示為準，查不到的欄位留空，不用 0 代替「不知道」。
2. 靠搜尋得到的數字會標記來源與信心（高／中／低），並寫進食物庫的備註。
3. **AI 產出的結果一律要你按確認才計入當日。** 可以當場確認，也可以先丟進「待確認」佇列稍後處理。

食物庫裡每一筆都有來源標記：`營養標示` / `網路查證` / `AI 推估` / `手動輸入` / `內建參考值`。看到「AI 推估」或信心「低」的，建議找到包裝標示後手動校正。

## 七、食物庫的起始資料

`data/seed-foods.json` 內建約 36 項常吃食物，在「食物庫 → 匯入參考」可以一鍵匯入。**這些是常見公開參考值，不是逐項取自食藥署原始資料庫**，所以信心一律標為「中」，請以實際包裝標示校正。

要匯入完整的兩千多筆官方資料：

1. 到 https://data.gov.tw/dataset/8543 下載食藥署「食品營養成分資料集」（ZIP，免費，每 3 個月更新）。
2. 解壓縮取得 CSV，先確認欄位名稱：
   ```
   node tools/convert-tfnd.mjs --headers 原始檔.csv
   ```
3. 依結果調整 `tools/convert-tfnd.mjs` 裡的 `COLUMN_MAP`，再轉檔：
   ```
   node tools/convert-tfnd.mjs 原始檔.csv > data/tfnd-foods.json
   ```

官方欄位名稱在不同年度版本間有過差異，所以第 2 步不要跳過。

## 八、本機開發

ES modules 有同源限制，不能直接雙擊 `index.html`。在專案資料夾跑一行就好：

```
python3 -m http.server 8080
```

然後開 `http://localhost:8080`。
